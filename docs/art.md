# Regenerating the art

Most art is generated by scripts so you can restyle it. They need Python 3 and Pillow
(`pip install pillow`) and are run from the repo root:

```bash
python tools/art/generate_background.py levels/level_01/background
python tools/art/make_level_backgrounds.py
python tools/art/generate_tiles.py levels/common/tiles/kenney_industrial levels/common/tiles/data_center
python tools/art/generate_machines.py levels/common/machines/data_center
python tools/art/generate_projectiles.py
python tools/art/generate_pit_hazards.py
python tools/art/generate_icon.py icon.png
```

After regenerating, run `godot --headless --path . --import` so Godot re-imports the PNGs.

| Script | Produces | Tweak here |
|---|---|---|
| `generate_background.py` | level 1's background: 3 parallax layers + 2 LED layers, blurred for depth of field. Each layer is one *storey* of the hall (racks standing on a floor slab, a gantry with stairs and columns) that tiles vertically, so racks never float and the picture never ends. `W` and `H` must match `TILE_W` and `TILE_H` in `scripts/level/background.gd` | `BLUR_*`, colours, rack layout, `*_FLOOR` |
| `make_level_backgrounds.py` | the backgrounds of levels 2 to 5: colour-graded copies of level 1's layers, one folder per level (`levels/<level>/background/`) | `GRADES` |
| `generate_tiles.py` | themed ground, ledges, ladders, crates, spikes + regraded props | palette constants at the top |
| `fetch_captcha_images.py` | The pictures of the "I am not a robot" minigame, `assets/captcha/*.png`, and its 28 riddles (`assets/captcha/manifest.json`). The pictures are cartoon emoji of Google's Noto Emoji set (Apache License 2.0) downloaded as published (128 px, the size they are shown at), put on a soft pastel square and saved as small palette PNGs (about 3 KB each, 135 KB in all). Credits: `assets/captcha/CREDITS.md`. Each riddle ("I have two hands but I have never clapped...") has one answer picture and an `exclude` list of pictures that could also fit it, never shown with it; riddles never name their answer and are never about the player. To add a riddle or a picture, edit `RIDDLES` / `PICTURES` and run it again | `PICTURES`, `RIDDLES` |
| `generate_pit_creatures.py` | The creatures that leap out of the pits (the piranha is in `generate_pit_hazards.py`): the toxic waste's poisonous **puffer fish** (deflated, half and fully puffed-up frames), the lava's **fireball** (a glowing white-yellow head with a comet of layered orange flame and loose embers, three flicker frames) and the nuclear waste's glowing **eel** (four swimming frames). Drawn like the piranha: 8x supersampled, smooth outlines, a dark outline, a light from above. They are listed in `SpriteLibrary.PIT_CREATURE_PARTS`; the species are in `PitCreature.SPECIES` | the per-creature functions |
| `generate_ui_icons.py` | The three icons of the puzzle window in `assets/ui/`: `icon_firewall` (a steel shield with a brick wall and a flame; the window's title), `icon_lock` (a closed hazard-yellow padlock beside the instructions) and `icon_unlocked` (an open green one, shown when the puzzle is solved). Loaded with `AssetPaths.ui()`; the window's look is `scripts/ui/hack_style.gd` | `icon_firewall()`, `_padlock()` |
| `generate_pit_signs.py` | The four warning signs before the deadly pits (`sign_pit_poison`, `sign_pit_fire`, `sign_pit_nuclear`, `sign_pit_piranha`, 70x70 tiles in `levels/common/tiles/data_center/signage/`): a signboard on a short post with a hazard-striped yellow frame and a dark face, two red lamp lenses on tiny rods above the top corners (the game makes them glow, see `GlowPulse`), showing a green skull over crossbones, a flame, the radiation trefoil or the game's own robot piranha leaping half out of cartoon waves. Registered as the `decor_sign_pit_*` tiles; `scripts/level/pit_signs.gd` places them | the four `icon_*` functions |
| `generate_pit_hazards.py` | The deadly-pit art in `levels/common/pit_hazards/<kind>/`: recolours of Kenney's CC0 lava and water tiles (kept in `tools/art/sources/kenney_platformer_redux/`) for toxic waste, lava, nuclear waste and the piranha tank, plus the robot piranha drawn in four mouth poses (closed, slightly open, open, wide open) that the game flips through to make it bite, and an eye glow. The liquids' motion is `scripts/level/pit_liquid.gdshader` | `recolour()` values, the piranha drawing |
| `generate_projectiles.py` | The 12 throwable objects in `assets/projectiles/pixel_art/` (6 public-domain paintings shrunk to pixel art from `tools/art/sources/`, a cat photo and 5 everyday objects, drawn in code). A new object is listed in `SpriteLibrary.PROJECTILES` | the per-object functions |
| `generate_machines.py` | GPU rack, supercomputer, monitoring station, server tower + LED layers + shadows + the spinning fan blades (`machine_fan.png`). Also **writes `scripts/level/machine_fans.gd` and `scripts/level/machine_screens.gd`** (where each machine's fans and monitor screens sit), so commit those files after regenerating | the per-machine functions |
| `generate_icon.py` | the 512x512 app icon (`icon.png`) | colours, hero pose |

Brightness of the background layers is set at run time in
[scripts/level/background.gd](../scripts/level/background.gd) (`*_TINT` constants), not in the images.

The third-party art by Kenney (CC0) is the source for the character poses
(`assets/characters/kenney_platformer/`) and the base tile sprites (`levels/common/tiles/kenney_industrial/`);
`levels/common/tiles/kenney_industrial/NAMES.md` maps the pack's numeric file names to the descriptive names
used here. Each folder keeps its `License.txt`.

## Asset layout

Art is nested as `<root>/<component>/<style>/<group>/<file>.png`. Everything the levels share lives in `levels/common/`;
each level's own background is in its folder; the characters and thrown objects are in `assets/`. File names are never changed
by the layout, so a sprite's name is enough to find it, and `SpriteLibrary` is the only code that knows the folders.

```
levels/
  common/                          art shared by every level
    tiles/                         level tiles and props
      kenney_industrial/           the original Kenney set (CC0); NAMES.md maps its old numeric ids
        terrain/ structure/ equipment/ hazards/ lights/ signage/
      data_center/                 our themed replacements, same names and same category folders
        terrain/ structure/ equipment/ hazards/ lights/ signage/
    machines/
      data_center/                 generated machines (style)
        gpu_rack/ supercomputer/ monitoring_station/ server_tower/    image + _leds_a/_leds_b + _shadow
        parts/                     shared moving parts (the fan blades)
    pit_hazards/                   the deadly-pit liquids and the robot piranha
  level_01/ ... level_05/
    level.sablevel.json
    background/                    that level's five parallax layers
assets/
  characters/
    kenney_platformer/             Kenney's cartoon characters (style)
      player/ zombie/                the ten poses the game shows (see tools/audit_rules.json): <character>_<pose>.png
  projectiles/                     the throwable objects
```

How a name becomes a folder:

- **Tiles:** the first word of the name picks the category, for example `ground_start` -> terrain,
  `siren_blue` -> lights. The word-to-category table is `SpriteLibrary.TILE_CATEGORIES`.
- **Machines:** the machine is the name without the `machine_` prefix and without
  `_leds_a`, `_leds_b` or `_shadow`: `machine_gpu_rack_shadow` -> `gpu_rack/`.
- **Themed over original:** `SpriteLibrary.tile()` uses the sprite from `tiles/data_center/` when one
  exists with the requested name, and falls back to `tiles/kenney_industrial/` otherwise.

To add art: put the file in the right folder with the right name (a new kind of tile also needs its
first word added to `TILE_CATEGORIES`). `tools/tests/assets_test.gd` checks that every file is
where the rules say and that everything loads, so a misplaced file fails `tools/run_tests.sh`.
Godot creates the `.import` file next to each image the first time you import.
